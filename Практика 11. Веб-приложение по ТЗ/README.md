# Практическая работа № 11. Разработка веб-приложения в соответствии с ТЗ

Фронтенд (шаблоны, CSS, JS) работает с бэкендом Flask через формы, бэкенд работает с SQLite через классы-репозитории
(`app/models.py`). Работа с данными заявки:

| Операция | Кто | Где | Скриншот |
|---|---|---|---|
| Добавление | участник | `/requests/new`, `RequestRepository.create` | `1` |
| Чтение | участник видит свои, администратор все | `by_user`, `all`, `get` | `1`, `5`, `9` |
| Обновление | участник меняет помещение, оплату и число мест, пока заявка «новая» | `/requests/<id>/edit`, `update` | `2`, `3` |
| Удаление | участник отменяет «новую» заявку, администратор удаляет любую вместе с отзывом | `delete` | `4`, `11` |

## Смена статусов

Администратор переводит заявку вперёд по цепочке **новая → назначено → завершено** кнопками «Назначить» и «Завершить»
(`/admin/requests/<id>/next`, словарь `RequestRepository.FLOW`). Перескочить статус или вернуть назад нельзя: у «завершено» следующего статуса нет,
запрос получает 400. Изменить статус может только администратор, и только через форму с токеном CSRF.
Скриншоты: `5`, `6`, `7`, `8`.

## Отзывы

После статуса «завершено» у участника в списке заявок появляется кнопка «Оставить отзыв» (скриншот `9`), отзыв сохраняется один раз
(скриншот `10`) и показывается на странице мероприятия.

## Проверка

`tests/test_lifecycle.py`: переходы статусов, запрет перескока, права участника и администратора, защита от чужих заявок,
удаление заявки с отзывом, весь путь «заявка, назначена, завершена, отзыв». Всего 47 тестов, результат на `12_тесты.png`.
